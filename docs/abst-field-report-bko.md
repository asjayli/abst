# ABST 实践检验报告：bko 试点（2026-08）

> 本文是 [ABST 体系设计](abst-design.md)（Auto Business Statement Testing）的实践复盘，属经验性记录；方法论本体以设计文档为准。

## 一、背景与总量

- **对象**：bko 业务系统（tRPC + Next.js，另有 Android 端），路径 `/code/app/bko`。
- **既有测试体系**：单测 330 个全绿；web E2E 行覆盖约 34%；Android 测试刚起步。
- **ABST 落地物**（首轮在 `/code/app/bko/e2e/abst/`，二轮起迁至独立顶层 `/code/app/bko/abst/`）：`registry.json`（声明注册表）、`glossary.md`（词汇表）、`probes.mjs`（探针）、`verdict.mjs`（判定脚本）、`abst-report.json`（判定报告）。
- **首轮结果**：48 条声明，按 feature 分 8~9 个域登记；`C(G)` 从 68.4% 跑到 100%；**揪出 6 个生产 bug**。

## 二、被实践证实为真的（优点）

1. **按业务声明取证，天然打到测试体系的盲区**——最大卖点得到验证。`comments.list`、`publicList`、带标签的 `notes.list` 三个 API 在生产上全挂，既有体系没有任何一层发现：单测测孤立单元（mock 掉的 prisma 不会暴露输出契约断裂），E2E 卡在登录没走到那。ABST 探针按"业务承诺"做真实双账号组合调用，这些 bug 藏不住。一个测试体系的价值可以用它第一天揪出的 bug 数量度量——ABST 是 6 个。
2. **三叉定位真实发生**：SHARE-002 是声明错（侦察把"复用分支"误读为"取消后复用"，实际实现是"取消即死链"——而且实现更合理），走声明升版；HIST-001 是探针错（期望报错，实际返回空数组，隐私语义等价）；其余是实现错。三种失败各有清晰归宿，不是"红了就修码"。
3. **`C(G)` 第一次让覆盖率有了业务语义**："分享域 100%"比"行覆盖 34%"能回答的问题多得多。判重原则（quota/token 直接委托既有单测）省了大量重复劳动。
4. **注册表 + 稳定 ID 让测试资产可治理**：声明是活的、有版本的、可枚举的对象，而不是散落在各 spec 文件里的断言。

## 三、实践中真实撞到的（缺点）

1. **声明来源的循环论证风险——最严重**。初始 38 条声明是读代码反推的。代码→声明→验证代码，这条链永远自洽：能抓"代码 vs 代码声明的契约不一致"，但抓不到"代码和设计意图一起错"。本次 6 个 bug 全是前者。声明若不从 openspec/需求文档独立派生，ABST 就退化成"给现状盖章机"。SHARE-002 的误读还说明反推本身会出错。
2. **取证成本仍然高**。33 个探针手写，每个都要先搞清 procedure 的输入输出形状——光 `z.void` vs `z.object` × query vs mutation 的组合矩阵就试错三轮。声明到证据的距离并没有比写普通测试近多少。
3. **`DELEGATED` 是诚实性弱点**。设计强调回读（执行结果须经引擎确认），但实现里 static 证据等于"我说它存在"，e2e 委托没有回读套件最近一次结果。这部分靠纪律不靠机制。
4. **100% 的错觉**。`C(G)=100%` 只是"已登记声明的覆盖率"，登记本身不完备——server 有 20+ 个 router，只登记了 9 个域。weight 也是拍定的 3/2/1，无校准依据。
5. **`STALE` 没有落地**。声明升版/实现变更自动传播失效是设计里的自洁机制，实现里只有 README 里的一句纪律。

## 四、改进建议（按性价比排序）及设计回修映射

| # | 改进建议 | 设计文档回修位置 |
| --- | --- | --- |
| 1 | 声明派生锚定规格源：openspec/ 派生的才是独立应然；代码反推标 `derived-from: code`，信任降级、评审优先级最高。**这一条决定 ABST 是验证体系还是盖章体系** | §4.1 `derived-from` 字段、§五①、§三 |
| 2 | 探针脚手架自动化：zod schema 机器可读，从 router 定义静态生成 manifest（procedure 清单 + 输入形状 + query/mutation 形态），探针生成从手写降为填空 | §五③ |
| 3 | 回读落地：static 证据校验目标代码片段仍存在（锚点 grep）；e2e 委托读取最近一次套件运行结果文件；unit 委托校验测试文件内指定断言标记 | §4.3 `DELEGATED` 状态、§五④ |
| 4 | 失效传播自动化：`impl-refs` 实现文件清单进注册表，CI git diff 命中实现文件置 STALE；声明文本语义变更则升版回 DRAFT 重签 | §九、§4.3 |
| 5 | `C(G)` 旁加"域登记率"（已登记域/全部域）防 100% 错觉；weight 从缺陷史反推校准（出过高严重度 bug 的域加权） | §七 |
| 6 | 声明评审异构化：goal 级声明的 Three Amigos 会审，先用异构模型评审顶掉一轮（"这条声明的应然合理吗"），人工只处理分歧——复用 T→T'→OT 双链思想 | §五② |

## 五、第二轮落地（修订版新规）

按吸收首轮教训后的设计文档执行的第二轮（两笔提交：体系迁移 + schema 修复）：

**新规逐条对齐**

- ABST 独立顶层目录（§十）：`e2e/abst/` → `abst/`，npm scripts / CI / .gitignore 同步；
- `derived-from` 信任分级（§4.1）：存量 48 条标 `code`；新增 11 条 `spec`（openspec 四份规格派生）；
- 回读机制（§4.3、§五④）：static 证据锚点 grep 校验、unit 断言标记校验、声明 hash 变更自动失效——AUTH-008 锚点丢失当场被抓到并修正；
- 域登记率（§七）：报告显示 13/18 router，防 100% 错觉；
- 失效传播自洁（§九）：text+version hash 比对上期报告，升版即重新背书、实现变更即重新取证；
- 意图四册（§12.2）：宗旨册（手写草案）+ 功能矩阵册/声明册（从注册表同源生成）+ 词汇表；
- goal-per-feature + mission 追溯（§12.5）：12 条 goal 声明以 `refines` 边挂到 behavior/contract，判定机实现合取（GOAL-QUOTA 曾因 QUOTA-006 失败被正确拉红）——此机制已回写设计文档 §4.4。

**这轮又抓到的东西**

- QUOTA-006 牵出 dev 环境修复：`aiUsageEvent` 表模型在 schema 里但 prisma client 是旧生成物——`usageSummary` 在 dev 一直 500；
- 二次 schema 漂移：notesSchema 缺 `intentType`/`agentConfig`。同一坑第二次出现，教训是应把"prisma schema 变更 → 重生成 zod"做成 CI 静态检查；
- TRIG 探针发现 runNow/cron 路径不写 noteExecution（只有 intent 路径写）——规格说"每次执行写入历史"，典型的声明 vs 实现分歧点。

**体系级落地错误：签署被当成滞后待办（本轮最重要的教训）**

四册的人工逐条签署（MISSION-001 宗旨册等）被 AI 排到了覆盖率跑完之后的"未了结事项"里——C(G) = 96.5%（137/142 权重）被先行算出并展示，签署成为尾部待办。这暴露了当时设计文档的结构性缺陷：签署是流水线第⑤步（末位），而非前置闸门，AI 只是忠实地执行了一个错误的顺序。后果是微妙的：在未经批准的应然上算出高覆盖率，比没有覆盖率更危险——它给未背书的声明镀上一层"已验证"的外观，是盖章机的精致复发。

**设计回修**：设计文档据此引入 `DRAFT`（草案）入口态——未背书声明不得产生正式证据、不计入 `C(G)`、Gate 命中即拒；入库背书（Endorse）提升为生命周期第②步、整条流水线的咽喉（§五②）；背书随 text+version 的 hash 走（`endorsement` 字段），语义升版即失效须重签；度量体系新增"背书积压"指标且 `C(G)` 须与应然批准率成对输出（§七）。详见设计文档 §4.3、§五、§六、§七。

**二轮最终状态**

- C(G) = 96.5%（exec 模式，137/142 权重），0 VIOLATED，回归单测 330 全绿；
- 未了结 2 条，按 §12.1 本就不能由 AI 自闭环：MISSION-001（宗旨册草案待人工签署）、INTENT-004（summarize 双向链接需 agent 链路联调验收）——在报告里显式可见，是诚实条款要的效果；按修订后语义，这类未背书声明今后应计为 DRAFT 积压而非"未了结"；
- 待办：域登记率从 13/18 补齐剩余 5 个 router；探针 manifest 生成器（§五③的脚手架杠杆）。

## 六、一句话总结

ABST 的元模型（声明-证据-判定 + 单一覆盖率）经受住了两轮实践检验，取证的 bug 产出远超预期；两轮各暴露一个体系级问题——首轮是**声明的独立性**（派生必须锚定规格源，否则覆盖率越高自洽幻觉越强），二轮是**背书的时序**（签署必须是前置咽喉而非滞后待办，否则高覆盖率给未批准的应然镀金）。两者共同指向同一条底线：应然的合法化永远先于、且永远高于实然的度量。
